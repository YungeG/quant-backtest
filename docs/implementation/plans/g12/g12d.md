# G12D Atomic Publishing and Repository

## Outcome

Publish an already-validated Bundle and opaque exact stream payload bytes into a local directory CAS with atomic visibility, immutable prior identities, per-manifest cooperative locking, idempotent same-content deduplication, and current retrievability proof.

## Research authority

`docs/research/g12d-atomic-bundle-repository.md` freezes the local-path, retention-proof, locking, identity, failure, and cleanup contract. Status remains authoritative only in the G12D Acceptance Card.

## Frozen vertical slice

One concrete `LocalMarketBundleRepository` owns one `publish_market_bundle_v1` method. It reuses `MarketBundleManifest` and `MarketBundleRef`, validates exact stream payload coverage/hash parity, stages and verifies deterministic files, hardens them read-only, atomically renames to the final content-addressed directory, and verifies the final directory before success.

The retention proof binds only current verified retrievability. It has no clock, expiry, rebuild trace/window, decision-grade, or deployment meaning.

## TDD order

1. Import RED for eight Builder root exports.
2. First publish and exact persisted path/hash proof.
3. Exact second publish as idempotent success.
4. Input and payload mismatch failures.
5. Same-manifest lock contention and different-manifest concurrency.
6. Final conflict and existing staging refusal.
7. Inject write, verify, immutability, rename, final-fsync, and cleanup failures; prove no readable partial artifact or structured unmanaged state.
8. Tamper verification, static golden, and architecture/import boundaries.
9. Upstream G12A–C, WP-06A/B, and G06 regressions.

## Exclusions

No Reader/Cursor, Parquet/Arrow, URI/object-store abstraction, generic repository protocol, provider acquisition, coverage reports, wall clock, retention guarantee, rebuild proof, Runtime import, decision grade, or deployment authorization.
