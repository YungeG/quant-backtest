# G12C Bundle Validation and Manifest

## Outcome

Validate caller-order canonical Events before hashing, then derive the existing `MarketBundleManifest` with capabilities matching actual stream content and no partial success.

## Research authority

`docs/research/g12c-bundle-validation-contract.md` freezes the narrow logical-partition and provenance interpretation. The detailed Gate contract and status remain authoritative only in the G12C Acceptance Card in `docs/implementation/acceptance-matrix.md`.

## Frozen reusable boundary

G12C reuses `MarketEvent`, `MarketStreamManifest.from_events()`, `MarketBundleManifest.build()`, and external `MarketBundleRef.from_manifest()` parity. It never routes validation through a Reader because Reader sorting would hide caller-order defects.

## Frozen vertical slice

One tuple-only `validate_market_bundle_v1` function:

- validates header and exact typed Event envelopes;
- rejects Bundle-wide duplicate Event IDs;
- checks Event-time inclusion in the caller-supplied half-open coverage;
- enforces one `(event_type, capability)` classification per stream;
- enforces unique, strictly increasing ordering keys inside each stream without sorting;
- derives stream manifests and capabilities from unchanged caller subsequences;
- returns exactly one manifest or structured safe failure.

A nonempty stream subsequence is the G12C logical partition. Empty input is structurally valid but has no coverage or qualification meaning.
