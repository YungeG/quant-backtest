# G12K Universe and Corporate Action Coverage

## Outcome

Eventually prove Universe/listing and corporate-action consistency against explicit immutable closure declarations without implementing selection, entitlement, or accounting economics.

## Current status

`DRAFT / BLOCKED`. The G12C catalog hash is opaque; no production G12B listing, membership, or corporate-action Event schemas exist; and neither Universe nor action terminal-set closure declarations are frozen.

Research authority: `docs/research/g12k-universe-corporate-action-coverage.md`.

## Blockers to resolve first

Freeze and pass:

1. a canonical InstrumentCatalog artifact exact-bound to the G12C manifest hash;
2. G12B normalized listing-lifecycle and Universe-membership revision schemas;
3. a G12B normalized corporate-action announcement/lifecycle schema that preserves source/revision evidence but not accounting implementation;
4. explicit Universe and corporate-action closure declarations, including empty scope;
5. test-only mapping parity to G11C and G08F.

The proposed Event names in earlier analysis are not current repository contracts and must not be implemented as if already authoritative.

## Provisional implementation seam

After prerequisites pass, one pure Builder analyzer may return both reports atomically or one structured failure. Final public names, canonical bodies, failure precedence, and RED matrix remain unfrozen until the source schemas and declarations are approved.

## Readiness checks

Before changing `readiness` to `READY`, evidence must prove:

- exact catalog body/hash/manifest binding;
- listing and membership interval/revision/causality semantics;
- action lifecycle and supported semantics projection;
- declaration/Event/terminal-set exact cover and explicit empty cases;
- corrected revision and cancellation closure;
- deterministic failure precedence, atomicity, repeat hashes, and Builder-only imports;
- no Runtime/Kernel production dependency or duplicated economics.

## Non-goals

No Universe selection, lifecycle inference, survivorship certification, provider identifier mapping, entitlement, tax/rate calculation, fractional-share handling, accounting mutation, provider truth, Runtime boot branch, decision-grade claim, live use, or deployment authorization.
