# G12L-* Provider Source Qualification Template

## Outcome

Qualify one exact provider/dataset/version acquisition and mapping slice through
G12A-D without claiming generic provider correctness, market qualification, or
deployment authorization.

## Current status

`DRAFT / BLOCKED`. No provider or market is selected. This template freezes only
provider-neutral acceptance obligations; it does not freeze code or a provider
request/schema contract.

Research authority: `docs/research/g12l-provider-adapter-contract.md`.

## Frozen common boundary

Every concrete provider slice must prove:

- finite explicit acquisition scope and rejection of latest/current/now fallback;
- exact source authority/version and authoritative byte boundary;
- deterministic raw member identity and exact atomic G12A handoff;
- idempotent bounded retry/resume evidence;
- secret-free failures, logs, fixtures, provenance, and artifacts;
- offline unit/acceptance tests with no real network access;
- false decision-grade/deployment qualification flags;
- exact common failure precedence and immutable evidence hashes.

This common layer adds no production provider code, HTTP client, SDK, transport
Protocol, generic adapter interface, registry, factory, resolver, plug-in system,
retry framework, cache, credential store, filesystem abstraction, or network
test. G12A and G12B already own the executable providerless mechanics.

## Facts the concrete slice must own

The concrete plan must freeze from real provider evidence:

- provider request shape, authentication/signing, dataset and version;
- exact mapping from provider fields to existing G12B schemas;
- pagination, cursor, token, sequence, ordering, and terminal closure;
- revision, correction, supersession, cancellation, and archive closure;
- availability, calendar, session, outage, and gap claims;
- sanitized real raw fixtures, deterministic member keys, chunking, compression,
  and byte boundaries.

None of these values may be invented or generalized by this template.

## Exact failure precedence

The concrete slice maps provider conditions into this exact top-level order:

1. `CONFIGURATION_INVALID`
2. `PROVIDER_UNAVAILABLE`
3. `AUTHENTICATION_REJECTED`
4. `RATE_LIMIT_EXHAUSTED`
5. `SOURCE_SCHEMA_MISMATCH`
6. `NORMALIZATION_FAILED`
7. `DATA_GAP_DETECTED`

Multi-fault cases return the earliest applicable code. Ties use the earliest item
in the slice's frozen request/member order. Every failure returns no partial
`SourceSnapshot`, normalized Event set, manifest, or published Bundle.

## Per-provider READY checklist

Before changing a concrete `G12L-*` slice to `READY`, its plan and evidence must
freeze all of the following:

1. provider, dataset, contract version, source authority, and cited/archived
   authoritative documentation;
2. one finite request scope shape, including time/sequence boundary semantics and
   explicit rejection of latest/current/now/open-ended behavior;
3. exact request parameters, authentication/signing inputs, allowed transport
   dependency, and secret-redaction rules;
4. provider schema and field-to-field mapping to already-frozen G12B schemas,
   including event/availability/revision time semantics;
5. pagination/cursor/token/sequence order and proof that the requested set closes;
6. revision/correction/supersession/cancellation terminal-set closure;
7. provider/calendar/session/outage/gap classifications and the evidence that
   authorizes each claim;
8. sanitized real raw fixtures for success, boundaries, closure, and every mapped
   provider failure condition—never synthetic guesses;
9. deterministic raw byte boundary, member-key/mode/chunk plan, declared hashes,
   and exact `SourceSnapshotProvenance` values for G12A;
10. expected G12A `snapshot_id`, content-tree hash, `provenance_hash`, and exact
    downstream fixture/manifest hashes;
11. offline uninterrupted, retry, interrupted-resume, duplicate-response, and
    exhausted-retry evidence proving final content identity is idempotent;
12. atomic failure evidence proving no G12A freeze handoff or partial downstream
    authority after any missing/failed page, member, revision, or correction;
13. secret-scanning/redaction evidence for fixtures, logs, structured failures,
    provenance, URLs, headers, and exception handling;
14. unit/acceptance commands that run under G00 network isolation using only
    injected provider-specific fakes and committed byte fixtures;
15. exact mapping to the common failure precedence, false qualification flags,
    immutable artifact hashes, and no claim that G12H, G12I, G12K, G12L, G12M,
    decision-grade, live, or deployment authority is READY.

Until every item is exact, the slice remains `DRAFT / BLOCKED`.
